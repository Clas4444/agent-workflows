# Verification architecture refactor

Base revision: `569205f4bb6a058884143510698fbdf2542c1fb2`.

## Objective and resulting structure

The previous validator mixed metadata checks with local Loop conventions.
It is now a repository-level coordinator over three modules: manifest parsing,
supported skill metadata and project policy. The default command still runs
all checks. An explicit `--profile format` omits local policy but keeps manifest,
copy identity and bundled-runner integrity; it cannot write the full summary.

`AGENTS.md` documents maintainer commands, canonical ownership and trust
boundaries. `docs/ARCHITECTURE.md` maps responsibilities. `schemas/` publishes
the existing manifest shape independently of the catalog release number.
README, contribution instructions, validation guidance and CI reference the
new structure together.

## Verification

- Before changes: **89 tests passed**, Windows/Python 3.12.14, 10.286 seconds.
- After changes: **101 tests passed**, same environment, 10.498 seconds.
- New tests cover minimal metadata versus Loop policy, unchanged default gate,
  copy-integrity/path checks under the diagnostic profile, preserved imports,
  script/module CLI entry points, invalid profiles and summary-write rejection.
- Manifest contract tests compare the published roots/names and representative
  valid/invalid mutations with the production reader. These do not implement
  or certify a general-purpose JSON Schema validator.
- Full validator, format profile, Python compilation, canonical bundled-runner
  synchronization and whitespace checks passed locally.

The existing runner regression suite still exercises timeout, malformed status,
stream handling, bounded capture, failed persistence and continuation behavior.
The 27 instruction files and standalone/bundled runners are unchanged. No new
model invocations were needed for this structural change; historical host
evidence retains its recorded scope. CI results must be checked on the pushed
commit separately from these local checks.

## Remaining scope

Arbitrary YAML parsing, runner-state/evidence schema publication, adversarial
model evaluations, MCP/A2A services and telemetry exporters remain separate work.
The new agent instructions do not provide runtime sandbox or permission
enforcement. This refactor adds no dependency or new external service.
