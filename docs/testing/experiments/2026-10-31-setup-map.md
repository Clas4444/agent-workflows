# Workflow setup and map evaluation

Model attempts ran on 2026-10-31; analysis and repair verification continued on
2026-11-03. This campaign does **not** establish that a map generally saves tokens
or time. It demonstrates a usable setup design and a navigation benefit in one
source-change case, also obtained with the graph alone. In the policy-conflict
case the map incurred more reads, tokens and time than the graph.

## Protocol and prompt classes

The model was `gpt-6.1-sol`, low reasoning, through Codex CLI
`0.166.0-alpha.5.1`. The human authorized at most 21 attempts including setup.
All 21 were spent; no additional models were called during the final review.
See the [sanitized protocol](../../evidence/setup-map-20261031/protocol.json),
[observations](../../evidence/setup-map-20261031/observations.json) and
[setup capture](../../evidence/setup-map-20261031/setup.json).

An **idea-complete prompt** states the user's whole intended outcome, constraints
and client artifact interface. It need not prescribe the solution, hidden tests,
exception handling or expected answers. An **oracle-rich prompt** additionally
supplies such solution/testing/exception guidance. Withholding numeric answers
alone does not make a prompt idea-complete rather than oracle-rich. Earlier
batching reports have explicit terminology corrections; their measurements stay
at their original pins and are not pooled here.

The corrected design call received the same release-readiness client contract as
execution: reconcile policy authority, item blockers, costs and unknowns; write
an assessment with specified fields; draft only. Expected values, the grader and
test recipes were outside candidate projects. Output schema and access adapter
are experimental/client interfaces, not instructions for solving the case.
The setup model saw placeholder sources before business values were populated.
It produced a three-step authority/items/draft graph, exact file pointers and a
map. Validation and a manual contract review passed before execution.

Two cases each had three arms: idea alone, idea plus graph, and idea plus the
same graph and map. Installed project skills were present in every arm: this is
not a skill-free or isolated-host comparison. Update order was idea/graph/map;
conflict order reversed it. Each cell has only one attempt. The update case
copied the same earlier real model assessment to each arm, then changed current
sources. This tests a fresh-process handoff, not native chat continuation.

The frozen grader checked status, separate Decimal currency totals, clarification,
publication, current source hashes and unchanged inputs. Update also required
the exact pending blocker. Conflict allowed differing interpretations of blocker
IDs while requiring grounded, unique IDs and an unresolved authority conflict.
Twelve primary grader controls and five additional rubric controls passed. The
additional rubric (nonempty rationale, grounded IDs, permitted files) was sealed
before execution; its hashes were rechecked during analysis. It does not grade
every nuance of prose. All five completed outputs passed both rubrics.

## Observations

Input/cache tokens are aggregate CLI turn counters across tool interactions;
cached input is a subset of input. Output is reported separately. These are not
currency costs or unique prompt lengths. Times include CLI/tool execution and
service latency. Source reads count adapter events, including rereads; they are
not an operating-system read monitor.

| Changed sources | Graph + map | PASS | 29.077 | 154950 | 119552 | 960 | 10 | 0 |

In the update case, map versus idea used **8.82% less elapsed time** and **41.18%
fewer source-read events**, but **6.56% more input tokens**. Graph alone used
15.89% less time than idea. Map versus graph took **8.40% more time**, **2.88%
more input tokens**, and the same number of source reads. A navigation benefit
cannot be assigned uniquely to the map.

In conflict, map versus graph took **46.22% more time**, **21.92% more input
tokens**, and **61.90% more source reads**. Both preserved the unresolved policy
conflict and declined publication. The idea attempt hit the account usage limit,
returned exit 1 without a completed turn/usage record or assessment, and remains
BLOCKED. Its partial elapsed time is not a successful baseline. No average
percentage reduction across these cases is justified.

Corrected setup separately cost 87.746 seconds, 408317 input (355584 cached) and
3154 output tokens. This setup cost is excluded from the execution table and
must be considered before claiming amortized savings. There is no measured
break-even point.

Both map arms read the map and graph once. Neither called the routing helper;
no execution arm called select/advance/check-map. Update arms did not read skill
files; conflict map read knowledge/table, graph read knowledge/work/table, and
idea read knowledge before capacity failure. Thus map consumption is observed,
but full binding/route/cycle adherence and automatic stale-map rejection by a
real model remain NOT_VERIFIED. Installed helpers themselves are tested locally.

## Failures retained and repairs

The first protocol consumed 14 attempts: two setup designs, an interview smoke
call, ten completed execution observations and one interrupted update attempt.
The setup request omitted the client output/write contract. Designs introduced
extra ledger/draft/check artifacts while execution permitted only assessment and
cursor files. Business-output PASS under that mismatch cannot establish design
adherence; those observations are excluded from efficacy comparisons. Raw
attempts are retained privately. The interview asked three relevant questions;
that is a smoke observation, not proof of interview completeness.

The remaining seven attempts used the corrected contract: one reviewed setup
and six execution attempts, including the capacity failure above. No failed or
interrupted attempt was replaced or counted as a successful repetition.

Three concrete defects were reproduced and repaired:

- `map --project` ignored its project argument. Rendering now uses that project.
- A copied hash label could not verify the rest of a map. New `check-map` compares
  the complete canonical rendering against the graph and selected project,
  rejecting modified/stale/cross-project maps. This verifies identity, not source
  freshness or task success.
- Existing directories were accepted as exact source pointers, allowing broad
  archive scope. Project-aware check/render/export now reject directories and
  paths resolving outside the project before export; future output files remain
  permitted. Without `--project`, a structural graph check cannot inspect files.

Setup instructions now capture client artifacts, write/tool constraints and exact
source files before design. The corrected setup followed this contract in one
observed run. No model evidence shows guaranteed future compliance or savings.

## Verification boundaries

Focused setup tests: 29 discovered, 28 PASS, one platform skip on 2026-11-03.
An initial restricted-sandbox run encountered temporary-directory permission
errors; the same tests passed with the authorized Windows temp access. Full
publication verification passed all 14 gates: 392 tests, 390 PASS and two skips;
16 evidence indexes / 189 artifacts and documentation navigation passed. The
[local gate summary](../sessions/setup-map-20261103.json) records the unchanged
verification input fingerprint. Global installation and remote CI were not tested
by these local gates. An intermediate publication check became STALE when the
evidence files and their cross-platform LF rule changed; its raw result is
retained and is not cited as final verification.

Native picker testing is BLOCKED: the computer-use skill prohibits automating
the ChatGPT desktop UI. Only window inventory was inspected. Native discovery,
native chat resume, isolated skill-free A/B, automatic model routing/restoration
and general efficiency remain NOT_VERIFIED or NOT_RUN. Remote CI is checked
separately from local gates. The earlier approval-review rejection occurred
before model invocation; the human then explicitly authorized this 21-attempt
campaign. No global skill files were changed.

The [byte index](../../evidence/setup-map-20261031/published-hashes.json) covers
sanitized artifacts. Private raw requests/traces and machine-specific maps are
not published; hashes alone cannot reconstruct or independently authenticate
those executions. This packet is an observation record, not a public replay
harness or a statistical estimate of average savings.
