## Windows investigation

Earlier attempts on Python 3.14 reported a 5-second timeout in
`test_invalid_executable_preserves_launch_error`. A proposed MZ-header precheck
was removed because it only bypassed the case without establishing cause.
With unchanged runner code, the current explicit unsandboxed focused test passed
in 0.066 seconds and raised the expected OSError. Sandbox TEMP access failures
were separately observed in fixture tests. This does not prove sandboxing caused
the earlier timeout: that causal attribution remains unresolved. Do not present
the patch as a process-launch fix.
