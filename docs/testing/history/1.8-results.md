## Scope and implementation

The repository had 39 skills centered on software work. This update adds six
distinct utilities in three groups: writing/source summaries (`loop-write`,
`loop-summarize`), meetings/organization (`loop-meeting`, `loop-organize`) and
decisions/learning (`loop-decide`, `loop-learn`). The catalog now has 45 skills
in twelve disjoint navigation groups and 48 fixed primary-route cases.

Eight overlapping install bundles select a small set by need. The new installer
uses the existing sync preflight/backup engine with an optional keyword-only
selection. Existing full-sync CLI/API behavior remains unchanged. Unknown or
empty selections cannot fall back to a full install. Read-only checks, preserved
unselected files, backup behavior and bundled-runner copying are tested separately.

The [installation guide](../../guides/install-by-need.md) covers non-programmer agent
requests, CLI examples, manual copying, paths with spaces, checks and host activation.
[Everyday examples](../../guides/everyday-work.md) explain Do/Do not boundaries.
The role guide/SVG adds everyday writer, organizer and learner recommendations.

## Session alignment safeguards

`scripts/verification_session.py` records the explicit session ID, interpreter,
timestamps, all ten fixed gates, non-empty unittest discovery, raw log hashes
and before/after hashes of the declared verification inputs. It rejects an
existing output directory, preserving previous failures. A source change during
execution yields STALE; a later edit, different session or missing gate cannot
verify as current. Tests include those negative controls and zero-test discovery.

The report declares its exact input scope. It pins code, tests, schemas, skill
copies, CI, metadata, README and guide/fixture inputs; raw logs and session-report
prose are outside the pin. This avoids self-hashing published report text.
Hash checking detects drift, but is not authenticated attestation of a manually
forged report. Final campaigns and publication checks are recorded below.

Two defects were found in the newly written campaign recorder before finalization:
it initially selected a nested child's test-count summary, and a nested exported
folder could inherit the parent repository's HEAD. Failing regressions were
recorded before both fixes. Counts now use the outer suite's final summary;
Git identity is recorded only when the selected root is the actual Git top-level.
These are development-time recorder defects, not fabricated old-repository bugs.

The first two 220-test campaigns are retained as
`sessions/noncode-1.8-initial-312.json` and `sessions/noncode-1.8-initial-314.json`.
They passed their recorded inputs, then became stale after the recorder/regression
change. The actual verifier rejected them for the new checkout. They are not the
final current-source results. Pre-commit records explicitly retain a dirty
working tree and its base HEAD; the input fingerprint, not that old HEAD alone,
identifies the tested implementation.
